# 27 October 2026 — implementation and testing summary

Release: **Resideo Native 0.3.1**, the first GitHub release after 0.1.8.
Intermediate versions were local test archives. The attached 0.3.1 sleep-fix
archive is the runtime source; this publication updates the evidence and release
workflow without adding frost controls or changing the tested thermostat logic.

## What changed since 0.1.8

| Area | Final behavior |
| --- | --- |
| Cloud schedule actions | Read and replace selected heating/DHW day lists with `get_heating_schedule`, `set_heating_schedule`, `get_hot_water_schedule` and `set_hot_water_schedule`. Response actions expose revisions and normalized values. |
| EMEA handling | Import variable period counts and grouped-day routines as day lists. Filter GET-only `periodType`/`isCancelled` fields from EMEA writes across the complete outgoing week. Convert temperatures using the device rules. |
| Day/period deletion | Delete one row or clear an eligible day; preserve untouched days. Permit 0–6 periods per supplied day while retaining at least one populated weekday and weekend day for heating edits. DHW does not inherit that heating constraint. |
| DHW timing | Enforce the app's 10-minute grid before PUT. 07:10 is valid; 07:05 is rejected without rounding or sending a command. |
| Readback | Observe up to five GETs after a single PUT (0, 1, 2, 4, 8-second delays). Normalize harmless ordering/time/precision differences. Return unconfirmed data when accepted delivery cannot be verified; never replay the PUT automatically. |
| Revision/conflict handling | Re-read before saving and compare the expected revision. Unknown/geofence-only responses are not treated as proof of an empty schedule. No household routine or temperatures are silently installed. |
| Visual editor | Load cloud data, edit/add/delete/copy periods, export a cloud backup, import a backup into a draft, review before Save and keep drafts on errors. Editor links scope account and thermostat correctly. |
| Device-page entry | A visible Schedule editor entity opens the selected thermostat. The sidebar is optional, with Add scheduler to sidebar Off by default and saved per account. |
| Native schedule On/Off | A Heating schedule switch uses the app's Schedule/Status control. It preserves the routine and remains separate from HVAC mode and manual holds. |
| Geofencing switch | A real left/right switch: On opens Home/Away setup; Off opens timed setup. Both remain over the current HA page and require review/confirmation/Save. Cancel preserves the actual cloud mode. Mode is read at startup, periodically and after action readback. |
| Sleep | Shared create/edit/remove sleep controls in both popup and full editor. Overnight times are supported. The final legacy serializer sends a single `sleepMode.triggers` entry with all seven days; readback checks day coverage, times and temperature. |
| Validation and errors | Bounded sanitized API rejection details, fail-before-write input checks, no optimistic mode confirmation, versioned browser assets and removal of the obsolete Geofencing Press entity. |
| Frost | Keep native HVAC Off. Document the thermostat's own frost protection; add no frost entity, configuration switch or substitute heat hold. |

Phone location registration and permissions remain in the official Resideo app.
First-time creation/conversion remains outside the physical test evidence.

## Frost and the hold-order observation

[Resideo's specification](https://homecomfort.resideo.com/sites/Romania/ro-RO/Pages/ProductGroup.aspx?cat=HW-TOEM&catpath=1.2.1.6.1&pid=Lyric+T6+Smart+Thermostat-18717%28HW-TOEM%29)
documents integral 5°C frost protection in Off. The requester reports this is
fixed, has no app settings page and now uses real Off. They tested Off command
acceptance, not a room cooling to the frost threshold. The APK's adjustable
FreezeProtection UI is gated for other thermostat models; its separate
humidifier frostIndex is not Jasper frost configuration. No new frost control
or raw account-response request is needed.

The requester also reported that editing temperature during a permanent hold
can make it temporary. Their workaround is to set temperature first and then
apply Permanent hold. Record this as an observation, not a newly verified fix.
